Teaching Tip: Ask students: "Why would you build a coded prototype instead of just showing a Figma prototype?" — Answers should converge on: authentic interaction states, device portability, and dev-handoff fidelity. The question surfaces real trade-offs, not a false hierarchy.

💬 Refinement Prompts — After First Generation

Send these as follow-up messages in the same Antigravity conversation to iterate on the prototype.

🎨 Restyle
Change the primary button to a coral red gradient. Increase the heading font to 22px. Add subtle box-shadows to the input fields (0 2px 8px rgba(0,0,0,0.08)). Keep everything else the same.

✨ Add Micro-Interactions
Add hover and active states to all interactive elements. Cards should lift 6px on hover with a shadow increase. Buttons should scale to 0.97 on press. Add a 0.25s ease transition to everything. Input fields should show a coloured focus ring.
Click to copy
📱 Make Responsive
Make this fully responsive. On screens under 640px: stack all columns to single column, increase all tap targets to minimum 44px height, reduce headings by 15%, and add 16px horizontal padding to the body. Use a mobile-first approach with CSS media queries.

⏳ Add Loading & Success States
Add interaction states to the primary submit button: (1) Default state (current), (2) Loading — show a spinner, change label to 'Processing...', disable the button, (3) Success — green background, checkmark icon, label 'Done!'. Transition automatically from loading → success after 1.5 seconds. Wire this to a button click.

🌙 Dark Mode Toggle
Add a dark mode toggle button in the top-right corner (moon/sun icon). When activated, invert the background to #0d0d14, use white text, darken all cards to #1a1a2e, and adjust input field backgrounds to #1e1e2e. Store the preference in localStorage so it persists on refresh. Animate the transition with a 0.4s ease.

🎯 Writing Better Prompts

Specific context + named components + colour/tone direction = dramatically better output.

❌ Too vague
"make a login page"
✅ Specific
"Login screen for a meditation app, calm blue tones, email + password + Google SSO, centered card layout, 400px max width"
Prompt anatomy checklist
✦ App context — what kind of app, who uses it
✦ Screen purpose — what task it enables
✦ Named components — list each UI element
✦ Visual direction — colours, style, feel
✦ Output format — "single HTML file" or "HTML + CSS"
Teaching Tip: Run this live in class — open Antigravity, paste a starter prompt, and show the output in under 60 seconds. Then ask a student to describe their own project screen and prompt it live. The gap between "vague prompt" and "specific prompt" outputs is the most memorable lesson here.
